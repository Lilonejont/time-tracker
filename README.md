# Учёт рабочего времени

Небольшое веб-приложение для учёта времени сотрудников. Можно добавить сотрудника, запустить таймер с описанием задачи, остановить его и посмотреть записи с общим временем за любой период. Данные лежат в SQLite, поэтому после перезапуска ничего не пропадает.

Демо: http://time-tracker.31.77.131.97.sslip.io/ (данные вымышленные, менять их может любой).

## Запуск

Нужен Node.js 22.13 или новее. Внешних зависимостей нет, `npm install` не требуется.

```bash
npm start        # http://localhost:3000
npm run seed     # по желанию: тестовые сотрудники и записи
npm test
```

База создаётся сама в `data/timetracker.db`. Порт и путь к базе меняются через переменные `PORT` и `DB_PATH`.

## Как устроено

Используются только встроенные модули Node.js: `node:http` для сервера, `node:sqlite` для базы и `node:test` для тестов. Для такой задачи фреймворк лишний, а без зависимостей проект запускается одной командой.

Вся логика в `src/service.js`, она не знает про HTTP, и её удобно тестировать. `src/server.js` разбирает запросы и отдаёт файлы из `public/`. Интерфейс на обычном JavaScript, без сборки.

Что стоит знать о поведении:

- У сотрудника может идти только один таймер. Повторный старт вернёт ошибку 409. То же правило закреплено уникальным индексом в базе.
- Если задача шла через полночь, в отчёт за каждый день попадает только его часть времени.
- Незавершённый таймер в отчёте считается до текущего момента. После перезапуска сервера он продолжает идти, потому что в базе хранится только время старта.
- Дата «по» в отчёте включается целиком.

## Тесты

`npm test` запускает 18 тестов. Проверяются, в частности:

- повторный запуск таймера, пока он идёт (ошибка, вторая запись не появляется) и запуск заново после остановки;
- пустой отчёт: когда сотрудников нет вообще и когда за период нет записей;
- задача на границе периода и незавершённый таймер;
- сохранение данных после закрытия и повторного открытия базы;
- ошибки ввода и коды ответов API.

Время в тестах подменяется, так что они не ждут реальных секунд.

## Найденные ошибки

1. Тесты сначала вообще не запускались. В скрипте было `node --test test/`, а Node 24 не принимает папку как аргумент. Исправлено на `node --test "test/*.test.js"`.
2. Можно было добавить «Анну» и «анну» как двух разных сотрудников. Уникальность имени была сделана через `COLLATE NOCASE`, но в SQLite он работает только для латиницы. Это поймал тест. Теперь имя в нижнем регистре хранится в отдельной колонке с уникальным индексом.
3. После нажатия «Старт» отчёт не обновлялся, и задача появлялась в нём только после остановки. Нашлось при ручной проверке в браузере.
4. Если начало периода позже конца, появлялась ошибка, но на экране оставался старый отчёт. Теперь он очищается.
5. В тёмной теме белый текст на светлых кнопках плохо читался. Цвета поправлены.
